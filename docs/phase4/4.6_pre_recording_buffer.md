# Phase 4.6: Pre-Recording Buffer

## Data Flow
`rtspsrc` -> `rtph265depay` -> `h265parse` -> `appsink` ==> `PreBufferRing` (Memory) ==> `appsrc` -> `splitmuxsink`

## Keyframe Strategy
GStreamer tags non-keyframes with `GST_BUFFER_FLAG_DELTA_UNIT`. Frames without this flag are IDR/Keyframes. 
When backfilling, we calculate `eventTs - 30s`, find the frame at that timestamp, and then iterate *backwards* until we find an IDR frame. This guarantees the resulting `.mp4` begins with a full picture and is instantly playable. If no IDR is found, we drop the backfill and wait for the *next* live IDR to start recording.

## Memory Budget Model
The `PreBufferManager` maintains an atomic counter of all bytes currently held in all `PreBufferRing` instances.
* **Max Global Memory:** 2GB (2048 MB)
* **Allocation:** Before adding a frame to a ring, the ring requests quota from the Manager.
* **Eviction:** If the quota is exceeded, the Manager invokes `EvictOldest()` on registered rings (Round-Robin) until space is freed.

## Crash Persistence
Configurable via `IPreBufferPersistence`. Currently implemented as a Stub. When fully enabled in 4.7, it will memory-map the Ring Buffer to a rolling disk file so that if the service crashes *during* a pre-buffer phase, the 30s lead-up is not lost.
