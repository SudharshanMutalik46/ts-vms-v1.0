# Phase 4.11 - Recording Performance Tuning & Scale

## 1. Test Environment Specification
* **OS:** Windows Server 2022 / Windows 11 Pro (Build 22631)
* **CPU:** AMD Ryzen 9 5900X or Intel Xeon Gold 6230 (Minimum 8 Cores / 16 Threads for 128 cams)
* **RAM:** 16GB DDR4 ECC (Target usage < 4GB)
* **Storage:** NVMe SSD (e.g., Samsung 980 Pro) or Enterprise RAID 10 Array.
* **Filesystem:** NTFS, 64KB Cluster Size (Recommended for large video segments).

## 2. Workload Definition
* **Concurrency:** 128 Cameras.
* **Stream Profile:** H.265, 30 FPS, ~3.8 MB/s (Megabytes) per stream -> ~30 Mbps bitrate.
* **Target Global Throughput:** 128 * 3.8 = **~486 MB/s** sustained disk write.
* **Segment Size:** 5-minute durations, Fragmented MP4 (1-second fragments).

## 3. Tuning Knobs & Defaults
* **`rtspsrc latency`**: Set to `200ms` (down from default 2000ms) to reduce ingest memory footprint.
* **`queue max-size-time`**: Set to `2000000000` ns (2 seconds). Drops frames if disk stalls longer than 2s to protect RAM.
* **`mp4mux fragment-duration`**: Set to `1000` ms. Crucial for keeping live-to-file latency <2s. Flushes playable chunks to disk immediately.
* **`SegmentWriter Batch Size`**: 4MB chunks to minimize `WriteFile` syscalls.

## 4. Known Limits & Scaling Expectations
* **Disk I/O Ceiling:** Standard SATA III SSDs will cap at ~500 MB/s. To scale beyond 128 high-bitrate cameras on a single node, NVMe or RAID striped arrays are strictly required.
* **Network:** 128 cameras at 30 Mbps = ~3.8 Gbps. Requires a 10GbE NIC on the recording server.
