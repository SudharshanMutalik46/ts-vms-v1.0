# Phase 4.1 Storage Architecture Design

## 1. Tiered Storage Strategy
TS-VMS utilizes a tiered architecture to balance cost against immediate read/write performance.
- **Hot Tier:** Enterprise NVMe or SSDs. High IOPS. All new video segments are initially written here.
- **Warm Tier:** HDD arrays (e.g., RAID 6/10). Moderate IOPS. Used for medium-term evidence retention.
- **Cold Tier:** High-density SATA, NAS, or Cloud integration. Low IOPS. Used for long-term archiving.
Files are naturally allocated to the Hot tier. A background lifecycler service (Phase 4.2) will later be responsible for moving older files down the tiers.

## 2. File System Layout
We avoid complex database lookups for standard playback by encoding context directly into the physical directory paths:
`<volume_root>/<tenant_id>/<site_id>/<camera_id>/YYYY-MM-DD/HH/`

Example: `./data/recordings\hot\tenant-alpha\site-hq\cam-01\2026-02-26\14\`
This ensures fast directory iteration for timelines without blowing out inodes in a single directory.

## 3. Segment Naming Convention
Stable and sortable for seamless timeline assembly:
`<camera_id>_<UNIX_TIMESTAMP_MS>_<DURATION_SEC>_<SEQ_NUM>.mp4`

Example: `cam-01_1708945200000_60_00001.mp4`
This guarantees chronological ordering by default in the OS file explorer and minimizes metadata parsing.

## 4. Volume Selection & Spillover Algorithm
When the recording engine asks for a path to write a segment:
1. Planners inspect configured volumes for the preferred tier (usually "hot").
2. Volumes are sorted by Priority (1 = highest).
3. Planners evaluate realtime disk usage. If a volume's usage exceeds `max_usage_percent` or its free space drops below `reserved_free_gb`, it automatically selects the next eligible volume.
4. If the target tier is full, it spills over dynamically. If all storage is full, it throws `NO_STORAGE_AVAILABLE` and logging will fire CRITICAL.

## 5. Quota Management
Quotas are defined per tenant and per site.
Planners consult real-time quota trackers before issuing a storage path.
If an allocation would breach the quota limit (e.g., beyond 1000GB for a tenant), the planner returns `QUOTA_EXCEEDED` and halts new file creation for that tenant, emitting a WARNING log.

## 6. Disk Monitoring and Alerting
A background monitoring loop runs at configurable intervals (e.g., 60 seconds).
- Emits structured `EVENT storage.volume.status` logs tracking gb used/free.
- Hits `warn_at_percent` -> Fires `WARNING storage.volume.low_space_warning`.
- Hits `crit_at_percent` -> Fires `CRITICAL storage.volume.low_space_critical`.
Future integration natively hooks this into the NATS event bus.

## 7. NTFS Optimization Settings
For maximum throughput of 4MB raw H.265 chunks on Windows blocks:
- **Set 64KB Cluster Size:** Crucial for large AV files. Must be done manually via Disk Management during volume formatting. *Do not automate.*
- **Disable Last Access Time:** Safe to automate. Prevents the master file table (MFT) from doing a write every time a viewer scrubs video.
  - Run: `fsutil behavior set disablelastaccess 1`

## 8. Failure Modes & Recovery
- **Disk Full / Spillover Exhaustion:** Recording loops drop frames instead of crashing the process. CRITICAL alerts trigger.
- **Volume Missing (Offline/Unmounted):** Planner skips it seamlessly.
- **Permissions Error:** Fails gracefully on `EnsureDir()`, moving to next volume or dropping segment.
