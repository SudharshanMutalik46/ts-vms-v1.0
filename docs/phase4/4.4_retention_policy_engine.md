# Phase 4.4: Retention Policy Engine

## 1. Rule Model & Precedence
The Retention Engine evaluates `.mp4` video segments to determine if they should be deleted to reclaim storage space.
Evaluation order (Precedence: Camera > Site > Tenant > Global):
1. **Protected Segments:** If a segment is linked to an event, it is absolutely protected and **never** deleted.
2. **Days-based:** Segments older than `days_to_keep` are deleted.
3. **Size-based:** If the total size of stored segments for a scope exceeds `max_storage_gb`, the oldest segments are deleted until the size is under the cap.

## 2. FIFO Deletion Strategy & Safety
- **FIFO:** Deletions always occur strictly oldest-first.
- **Safety Threshold:** Segments newer than `never_delete_newer_than_minutes` (e.g., 15) are skipped, ensuring active recordings aren't touched.
- **Lock Check:** Files that are actively held open by Windows (sharing violations) are skipped.
- **Sidecars:** Associated files (like `.sha256`) are deleted concurrently with the primary `.mp4`.

## 3. Protected Segments (Manifest)
A manifest file mechanism is used to mark segments as protected:
- Location: `protected_segments/<cameraId>/<YYYY-MM-DD>.jsonl`
- Format: JSON lines indicating `{"segment": "cam-01_1708945200000_60_00001.mp4"}`
The engine parses these manifests at runtime to skip matching files.

## 4. Deletion Method (Trash then Delete)
Deletions occur in two steps (for safety):
1. **Trash:** The file is atomically renamed/moved to `.trash/<tenant>/<site>/<camera>/...`
2. **Delete:** Permanent removal from the trash. (Immediate deletion is supported if configured).

## 5. Audit Logging
Every action (deletion, skipping protected file, skipping locked file) writes a JSONL audit record to `logs/retention_audit.jsonl`:
```json
{
  "timestamp": "2026-02-26T12:00:00Z",
  "event_type": "retention.delete",
  "camera_id": "cam_01",
  "segment_path": "tenant1/siteA/cam_01/...",
  "reason": "days_policy",
  "policy_snapshot": {"days_to_keep": 7, "scope_applied": "tenant"}
}
```

## 6. Space Reclamation Verification
After a deletion pass, the engine verifies that disk space actually increased by comparing pre/post filesystem free space.
If the reclaimed space is significantly less than the bytes mathematically deleted, a `retention.space_verification_failed` warning is logged.

## 7. Failure Modes & Recovery
- **Disk Full / Missing Volume:** Logs critical error; skips to next healthy volume.
- **File Locked:** `skip_locked` mechanism bypasses it. Repeated locks over days trigger a warning.
- **Missing Manifest:** Treats as 0 protected segments; continues normal policy deletion.
