# Phase 4.9 - Recording Health Monitoring

## 1. State Model
Each camera's recording worker operates within a strict state machine:
* `STOPPED`: Not configured to record, or intentionally halted by the user.
* `ACTIVE`: Currently writing frames to disk.
* `PAUSED`: Temporarily suspended (e.g., waiting for motion event or schedule).
* `FAILED`: Pipeline crashed, disk unwriteable, or RTSP disconnected.
* `RECOVERING`: Attempting to reconnect or rebuild the pipeline after a failure.
* `THROTTLED_BY_LICENSE`: Recording blocked due to license limits.

## 2. Frame Drop Definition & Detection
A "frame drop" in the recording context means media was received but failed to persist to the segment safely.
**Detection Methods:**
1. **Buffer Discontinuity (Primary):** GStreamer `GST_BUFFER_FLAG_DISCONT` flag detected on a buffer after the parsing element (`h265parse`).
2. **PTS Gap Heuristic:** If `Current_PTS - Previous_PTS > 1.5 * Expected_Frame_Interval`, the gap is divided by the interval to estimate the number of dropped frames.
3. **RTP Sequence Gap:** Tracked at the ingest layer (jitter buffer).

*Calculation:* `Drop % = (Dropped Frames / (Valid Frames + Dropped Frames)) * 100` over a 60-second rolling window.

## 3. Disk Write Rate Measurement
* **Method:** The `SegmentWriter` pushes atomic byte counts to the Health Manager upon every successful async write completion.
* **Aggregation:** A background ticker (every 5s) calculates the delta of bytes written, storing it in a 30-second sliding window.
* **Metric:** `MB/s` (Megabytes per second) = `Sum(Bytes in Window) / 1048576 / Window_Duration_Sec`. 
* *Note:* Future Phase 4.1 integration will map camera output paths to Volume IDs for per-volume aggregation.

## 4. Alert Thresholds & Debounce Strategy
* **Debounce:** Alerts have a `cooldown_sec` (e.g., 30s) to prevent log spam.
* **Sustained Critical:** To trigger a `CRITICAL` alert, the threshold must be breached for `sustained_windows_for_critical` consecutive evaluation ticks. Otherwise, it fires as `WARNING`.

## 5. Metrics Exposure
* **HTTP:** `GET /status` exposes a complete JSON snapshot of all cameras, their states, and current sliding-window metrics.
* **Logs:** Structured JSON logs emitted with tags `recording.camera.failed`, `recording.disk.low_write_rate.warn`, etc.
