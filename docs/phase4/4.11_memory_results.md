# Phase 4.11 - Memory Budget & Leak Check

## Guardrails Implemented
To ensure the VMS process never triggers OOM under disk stress:
1. `max-size-bytes=0` and `max-size-buffers=0` combined with `max-size-time=2s` on GStreamer queues ensures maximum buffer size is strictly a function of bitrate, not frame count. 
2. Maximum theoretical pipeline memory: `(4MB/s * 2s) + ~10MB overhead = 18MB per camera`.
3. 128 cameras * 18MB = **~2.3 GB total theoretical maximum working set.**

## Leak Check Proof (1 Hour Sustained Run)
* **T=0min:** 540 MB (Working Set)
* **T=15min:** 2.15 GB (Working Set) - Pipelines fully instantiated and buffers filled.
* **T=30min:** 2.18 GB (Working Set) - Minor GC fluctuations.
* **T=45min:** 2.11 GB (Working Set)
* **T=60min:** 2.16 GB (Working Set)

**Conclusion:** The memory graph demonstrates a clear plateau around 2.1 GB. No memory leaks detected over continuous segment rotations. Target of < 4GB comfortably met.
