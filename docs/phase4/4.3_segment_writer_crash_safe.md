# Phase 4.3: Crash-Safe Segment Writer

## Pipeline Design
`rtspsrc protocols=tcp latency=200 ! rtph265depay ! h265parse ! splitmuxsink muxer=mp4mux max-size-time=<duration_ns>`
No decoding or transcoding occurs. The stream is written directly to disk.

## Segment Naming & Atomic Finalize Protocol
1. **Initial Write:** The `format-location` callback forces `splitmuxsink` to write to `<camera_id>_<timestamp>_<duration>_<seq>.tmp`.
2. **Close Event:** `splitmuxsink` emits `splitmuxsink-fragment-closed` to the pipeline bus.
3. **Flush:** The OS file handle is explicitly flushed (`fsync` / `FlushFileBuffers`) to ensure data is in non-volatile memory.
4. **Rename:** The `.tmp` file is atomically renamed to `.mp4`.
5. **Callback:** The metadata (path, size, time) is bubbled up to the Phase 4.2 worker for database indexing.

## Startup Corruption Detection
On service start, `StartupScanner::ScanAndClean()` runs:
* **Orphaned `.tmp`:** Any `.tmp` file older than `tmp_ttl_minutes` (default 10) is deleted.
* **Corrupt `.mp4`:** Files are opened and the first 8 bytes are read. If bytes 4-7 do not match `ftyp` (the ISO Base Media signature), or the file is 0 bytes, it is moved to `<camera_root>/corrupt/`.

## Failure Modes
* **RTSP Drop:** GStreamer throws an EOS or Error on the bus. The writer stops, leaves the current `.tmp` open, and emits the error. The Phase 4.2 supervisor handles the restart policy. The orphaned `.tmp` will be cleaned by the scanner on the next cycle or reboot.
* **Disk Full:** `splitmuxsink` will throw a write error. The pipeline halts.
